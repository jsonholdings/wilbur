## R3b verdict

R3b changed behaviour in the intended direction and cost nothing measurable: calls per round rose from 1.11 to 1.27 (the
first-turn hint fired in all 40 reps; the round-3 nudge never fired, because the model no longer made three single reads in
a row), and the todo pair hint fired 11 times, with `26_config_key_migration` down from 12.8 to 9.5 rounds. The tool-error
rate fell and no task lost a rep. It does not reach the 6.5 target: on this task set most rounds are edits, test runs and
debugging, which batching cannot merge. The target was set from a read-heavy estimate and is not reachable through
batching alone (M1 analysis).

Recommendation: turn both switches ON by default in the next release (2.73.0), since they help with no regression, and
retire the 6.5 target in favour of "no worse than B0" for rounds. The flip and release are not done yet.

## Errored-rep scoring check

`bench/runner.py` before 2.77.0 scored an errored rep by its tests, so an agent error could show as a pass with rounds=0
(BACKLOG `bench-errored-reps-scored-as-pass`, fixed in 2.77.0). The B0, M1 and M2 `run/tasks.jsonl` files (40 rows each)
hold no row with an `error` and no passing row with rounds=0, and neither do the other committed `tasks.jsonl` files under
`bench/results/`. A synthetic errored-pass row was counted by the same check. No number in this report changes.
